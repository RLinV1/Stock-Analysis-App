# Implementation record

Planned on 2026-10-13 after publishing `contracts/runs-api.v1.openapi.yaml` and `contracts/artifact-index.v1.schema.json`. The user asked to write code without running anything and to use orchestrated sub-agents; a sub-agent writes the client and tests under these rules. Nothing in this change has been executed yet.

The sub-agent added `mobile/src/api/contract.ts` (all request v1 bounds, closed-object validation, response types), `mobile/src/api/client.ts` (`createRunsClient`, `RunsApiError`, timeout via AbortController, text-then-JSON parsing so an empty 404 maps to `not_found`, shape checks on every success body, no token or raw fetch error text in messages) and `mobile/__tests__/runs-client.test.ts`. `PortfolioApp.tsx` now imports `LOOKBACK`/`EPOCHS` from the contract module. Review added a check that status and cancel responses name the requested run ID, plus a test case for a mismatched ID. Unverified assumptions for the first run: global `fetch` is assignable to the local `FetchLike` type; jest-expo provides `AbortController`; the timeout test uses real timers with a 5 ms limit. Jest, TypeScript and lint have not run; tasks stay open.

Added `list({ limit, cursor })` for the planned backend run list: limit 1–50 (default 20, always sent), optional UUID cursor, query built with `encodeURIComponent`, inputs checked before any fetch. `parsePage` requires an `items` array and a UUID-or-null `nextCursor` (missing becomes null); each item needs an ISO-8601 UTC `createdAt` string plus the status fields. Extra fields are ignored, like status parsing. Seven fake-fetch tests were added. Written by a sub-agent and reviewed; not executed.
