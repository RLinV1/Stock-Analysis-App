Security review on 2026-10-12 found an authentication bypass in `LocalOperatorFilter`: it skipped every request whose raw URI did not start with `/api/v1/`, but Spring MVC strips `;` path parameters before mapping, so an unauthenticated `GET /api;x=1/v1/runs/{id}` reached the controller and repository. A new MockMvc test reproduced it against the old filter (the request reached the stub repository instead of returning 401). The filter now fails closed: only the exact raw URI `/actuator/health` skips the bearer check; every other path, including `/actuator/health;x=1`, unknown paths and other actuator paths, requires the credential. Offline Maven test run: 9/9 Java tests pass (two contract, one changelog, six HTTP). Limitation: MockMvc, not a live Tomcat server, so container URI normalization is still unverified; fail-closed design does not depend on it.

The same review found a queue-blocking defect in the worker: `claim()` validated the stored request inside its transaction, so a row failing validation raised, rolled back and was reselected as the oldest claimable row on every cycle, starving all later jobs. The API validates before insert, so this needs schema drift or direct database writes, but it is now handled: an invalid stored request is marked `FAILED` with `error_code='invalid_request'` and no attempt row is created. A fake-cursor unit test covers it; worker tests pass 4/4. Real PostgreSQL behavior remains unverified until the Compose round trip.
